\section{Conclusions and outlook}\label{sec:conclusion}

The Nyquist/argument-principle criterion for linear autonomous time-delay
systems was turned into a fast and interpolable stability-chart tool. Marched
as a scalar ODE for the phase with an exact, automatically differentiated
integrand, the winding integral inherits the step-size control of modern ODE
software, and the integer residual of the count gives a dimensionless error
measure that follows the requested tolerance
($\max\varepsilon\approx100\,\mathrm{tol}$). Since the count needs only the end
value of the phase, the integration can also be dropped: the discrete
phase-unwrapping march sums exact phase increments between adaptively placed
samples, rejects steps that hide a root transition, and decides transitions
below the resolution of the number format by the side of the tracked root.
With $30$--$130$ evaluations for a median point it computes the benchmark
charts $\UwSpeedFourth$--$\UwSpeedTurning$ times faster than the phase ODE
without a single wrong count, and it resolves the Hopf boundary of the showcase
down to a parameter distance of $10^{-12}$.

The march is a loop of identical scalar steps, so its cost of
$\ParCpuOneUs\,\mu$s per point on one CPU thread divides almost exactly among
CPU threads and, on GPUs, in proportion to $1/n$ up to the effective
parallelism of the device. The fastest GPU measured computes a full-HD chart
in under a millisecond and an 8K chart in about ten milliseconds -- fast enough
to recompute the chart while a slider is moved -- and Float32 suffices. The
same kernel runs in any web browser on the viewer's own graphics hardware and
on rented cloud GPUs, where brute-force scans of four- to six-dimensional
parameter spaces take minutes to hours.\footnote{Both are ready to use. The
browser application is free and needs no installation:
\url{https://bachrathyd.github.io/InterpolatedNyquist.jl/webgpu/}. The Google
Colab notebooks in \code{gpu/colab/} of the repository run the GPU kernel --
optionally behind the same browser interface -- on a cloud GPU of the user's
own Colab account, billed in its compute units.}

The root estimate obtained during the same sweep makes the integer
root-counting map interpolable: one coloring shows the number of unstable
roots outside and the stability margin inside the stable domain; the
estimated root distance drives the multi-dimensional bisection method along
the true stability boundary (not along all D-curves); the largest inscribed
circle yields the most robust parameter point; and shifted lines yield
decay-rate contours. The characteristic function is extracted automatically
from a simulation-ready right-hand side, including nonlinear models and
singular mass matrices, and the identical workflow was demonstrated on
retarded, neutral, distributed-delay, differential--algebraic,
transcendental, high-dimensional and fractional-order systems. One modeling
lesson costs nothing and outweighs any tuning of the numerics: where a model
admits an open-loop/feedback split, the return difference $1+L(\lam)$ has the
same zeros, adds only open-loop poles, and has the exact order $n=0$ -- for the
phase ODE; the discrete march needs the denominators cleared again.

The limitations delineate the outlook. The method is restricted to autonomous
linear systems; for time-periodic coefficients time-domain methods such as
semi-discretization~\cite{insperger2011semidiscretization,bachrathy2026multiplication}
remain the practical choice. Away from the boundary the root estimate is of
first order unless refined, so the method complements full spectral solvers
when the deep spectrum is needed. A skipped root transition leaves the count
an integer; the cross-check with the tracked root, the parity test and the
step rejection of the discrete march detect or avoid it, but a pair of
transitions in the same direction within one step remains possible near
double-Hopf points, and a guaranteed count would require a different device,
such as interval arithmetic~\cite{johnson2009enclosing}. For neutral systems
beyond the essential instability threshold the count diverges with $\wmax$,
although the stable/unstable classification remains correct; the
fractional-order results are preliminary, in particular for shifted lines; and
a quantitative comparison with spectral collocation of the infinitesimal
generator is still to be made. For large models the cost is dominated by each
evaluation of $\Dfun$; the matrix determinant lemma~\eqref{eq:detlemma},
cached factorizations, large determinants on the GPU, neutral right-hand
sides in the automatic extraction, and coupling the real-time charts to
optimization loops are natural continuations.

\section*{Software and reproducibility}
The method is implemented in the open-source Julia package
\pkg{InterpolatedNyquist.jl} (MIT license,
\url{https://github.com/bachrathyd/InterpolatedNyquist.jl}), built on
\pkg{OrdinaryDiffEq.jl}~\cite{rackauckas2017differentialequations},
\pkg{ForwardDiff.jl}~\cite{revels2016forward},
\pkg{QuadGK.jl}~\cite{johnson2013quadgk},
\pkg{MDBM.jl}~\cite{bachrathy2025mdbm} and
\pkg{DelaunayTriangulation.jl}~\cite{vandenheuvel2024delaunay}. The GPU
implementation of the discrete march (\pkg{NyquistGPU}, with Google Colab
notebooks) is in the \code{gpu/} directory and the WebGPU browser application
in the \code{webgpu/} directory of the same repository. All figures and tables
of this paper can be regenerated by the scripts in the \code{paper/}
directory; the benchmark hardware and software versions are embedded
automatically in the manuscript.
